# Project CLAUDE.md Convention

> 토큰 절약을 위한 프로젝트 컨텍스트 표준. 기획·프로젝트 확정 시 항상 `CLAUDE.md`를 우선 생성한다.

## 트리거 (HARD-GATE)

다음 시점에는 코드 작성 전 반드시 `CLAUDE.md`부터 만든다:
- 새 프로젝트 시작 (저장소/디렉터리 초기화)
- 기획 확정 (PRD/TRD 합의 직후)
- 신규 서브앱 추가 (`apps/<new-app>`, `packages/<new-pkg>` 등)

기존 프로젝트에 `CLAUDE.md`가 없으면 첫 작업 전에 먼저 생성한다.

## 위치 — 프로젝트별 우선

루트 1개로 끝내지 말고, **서브 디렉터리(=논리적 모듈)마다** `CLAUDE.md`를 둔다. 해당 디렉터리 작업 시 우선 적용된다.

```
project-root/
├── CLAUDE.md              # 전역 (모노레포면 cross-cutting)
├── supabase/CLAUDE.md     # DB 스키마/RLS/마이그레이션 규칙
├── api/CLAUDE.md          # API 서버 규칙
└── web/CLAUDE.md          # Next.js 프론트 규칙
```

깊은 곳의 `CLAUDE.md`가 얕은 곳보다 우선한다. 중복 내용은 하위 파일에만 두고 상위는 cross-cutting만.

## 필수 섹션 (이 순서 그대로)

```markdown
# <프로젝트/모듈명> CLAUDE.md

## 절대 규칙
- 위반하면 안 되는 금지 사항 (맨 위)
- 비밀키 하드코딩 금지, 특정 폴더 수정 금지, 특정 명령 실행 금지 등

## 아키텍처
- 폴더 구조 (트리)
- 기술 스택 (프레임워크/언어/DB/배포)

## 빌드/테스트
- 개발 서버: `<command>`
- 테스트: `<command>`
- 배포: `<command>`

## 도메인 컨텍스트
- 비즈니스 용어 정의
- 데이터 흐름 (1-2 문단)

## 코딩 컨벤션
- 네이밍 규칙
- 커밋 메시지 패턴
- 모듈/패턴 규칙
```

## 분량 제한

- **300줄 이하**. 초과 시 reference 파일로 분리하고 링크로 대체.
- 표·리스트 위주, 산문 최소화.
- 코드 예시는 짧은 스니펫만, 긴 예시는 별도 파일.

## 작성 원칙

- 결론 먼저, 이유 나중 (`golden-principles.md` #4와 동일).
- 모호한 문장 금지: "필요시", "가능하면" 같은 표현은 규칙이 아님.
- 변경 가능 사항은 명시: "<버전 X 기준>", "<2026년 X월 결정>".
- 새 정보를 발견하면 그 즉시 갱신, 별도 세션 미루지 않음.
