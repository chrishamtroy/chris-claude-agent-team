# Agent Hub Skill

노션 **🛰️ AI 에이전트 협업 허브**와 Claude Code 에이전트 fleet을 잇는 운영 스킬.

- **자동 기록**: 서브에이전트가 끝날 때마다 `SubagentStop` 훅(`notion-subagent-log.sh`)이 노션 `작업로그` DB에 1행을 자동 추가한다. (이 스킬이 관여하지 않아도 동작)
- **이 스킬의 역할**: 프로젝트 생명주기(start/done/status)와 **승인 반영(sync)**.

## 노션 리소스 (source of truth = `~/.claude/notion/config.json`)

먼저 `~/.claude/notion/config.json`을 읽어 ID를 확보한다. 현재 값:

| 항목 | 값 |
|---|---|
| 프로젝트 data_source_id | `8ae69fdf-b2ff-4814-af97-68cdc957c862` |
| 작업로그 data_source_id | `a03e1c57-0c9f-48df-a32e-fe09d3e55e53` |
| 허브 페이지 | `37182fd1-783b-8138-b798-d282bc765df5` |
| 활성 프로젝트 포인터 파일 | `~/.claude/notion/active-project` |

- **프로젝트** 속성: `이름`(title), `상태`(시작/진행중/완료/보류), `담당 오케스트레이터`(adm/wd/mkt/ec/fin/edu/bd/bs/ceo), `시작일`(date), `완료일`(date), `요약`(text)
- **작업로그** 속성: `작업명`(title), `에이전트`(select), `프로젝트`(relation), `상태`(완료/실패), `승인`(승인대기/승인/반영완료), `소요시간`, `시각`(date), `요약`, `세션`

날짜는 절대 암산하지 말고 `date '+%Y-%m-%d'`로 구한다.

## 명령

### `start "<프로젝트명>" [오케스트레이터]`
프로젝트를 노션에 만들고 활성화한다.
1. `date '+%Y-%m-%d'`로 오늘 날짜를 구한다.
2. `notion-create-pages`로 **프로젝트** data source에 행 생성:
   - parent: `{ "data_source_id": "8ae69fdf-b2ff-4814-af97-68cdc957c862" }`
   - properties: `이름`=프로젝트명, `상태`="진행중", (있으면)`담당 오케스트레이터`=오케스트레이터, `date:시작일:start`=오늘
3. 생성된 페이지 ID(32자리 hex)를 활성 포인터에 기록:
   `printf '%s' '<PAGE_ID>' > ~/.claude/notion/active-project`
4. 사용자에게 노션 페이지 URL과 "이제 orchestrator에게 작업을 지시하세요. 각 에이전트 작업이 노션 작업로그에 자동 기록됩니다."를 안내.

이후 `SubagentStop` 훅이 추가하는 작업로그 행은 이 활성 프로젝트와 자동으로 relation 연결된다.

### `done ["결과 요약"]`
활성 프로젝트를 완료 처리한다.
1. `~/.claude/notion/active-project`에서 페이지 ID를 읽는다(없으면 사용자에게 알림).
2. `notion-update-page`(command `update_properties`)로 해당 페이지: `상태`="완료", `date:완료일:start`=오늘, (있으면)`요약`=결과 요약.
3. 활성 포인터 비우기: `: > ~/.claude/notion/active-project`
4. 완료 요약을 사용자에게 보고.

### `status`
읽기 전용 현황 보고.
1. 활성 프로젝트 ID를 읽고, `fetch`로 프로젝트 페이지 + 연결된 작업로그(relation `작업로그`)를 조회.
2. 최근 작업로그 N건(에이전트·상태·시각·요약)을 표로 요약해 보고.

### `sync` (승인 반영 — 반자동)
> 사용자가 "승인된 거 반영해줘"라고 해도 동일하게 동작.

1. 작업로그 data source(`a03e1c57-0c9f-48df-a32e-fe09d3e55e53`)에서 `승인` = **승인** 인 행을 조회.
2. 각 행마다 `작업명`·`요약`·`에이전트`·`프로젝트`를 근거로 **무슨 작업을 반영해야 하는지** 판단하고, 적절한 orchestrator/에이전트에게 위임해 **실제로 실행**한다.
3. 실행 결과를 그 작업로그 행(또는 새 작업로그 행)에 기록하고, 처리한 행의 `승인`을 **반영완료**로 업데이트(`notion-update-page` update_properties).
4. 처리한 항목 수와 결과를 사용자에게 보고.

#### 🚧 가드레일 (지식작업만 — 절대 규칙)
`sync`가 자동 실행할 수 있는 범위는 **되돌릴 수 있는 지식작업**뿐이다:
- ✅ 허용: 글쓰기/카피, 리서치/조사, 기획/전략 초안, 문서·리포트 생성, 분석, 코드 **초안 작성**(커밋·푸시 없이 파일만)
- ⛔ 금지(실행하지 말고 사람 확인 요청): `git push`, 배포(deploy/publish), 외부 발송(이메일/메시지/SNS 게시), 결제·송금, 데이터 삭제, 프로덕션 변경, 그 밖에 되돌리기 어려운 모든 행동

금지 범주에 해당하면 실행하지 않고, 해당 작업로그 행은 `승인` 그대로 둔 채 사용자에게 "이 항목은 되돌릴 수 없는 작업이라 직접 확인이 필요합니다"라고 보고한다.

## 폰/원격에서 쓰기
claude-forge가 GitHub에 push돼 있으므로(현 Stop 훅), **폰 클로드 앱에서 claude-forge 레포로 원격 Code 세션**을 열면 86개 에이전트 + 노션 커넥터가 그대로 동작한다. 집에서 노션에 `승인` 표시 → 원격 세션에서 `/agent-hub sync`(또는 "승인된 거 반영해줘") → 실행.

## 주의
- 토큰/연동 미설정이면 자동 기록 훅은 조용히 비활성(무해). 설정은 `~/.claude/notion/`의 `token`·`config.json`.
- 모든 ID는 코드에 박지 말고 `config.json`을 우선 신뢰한다(값이 바뀔 수 있음).
