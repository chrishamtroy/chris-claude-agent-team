# /brainstorm 스킬 — 구조화된 브레인스토밍 파이프라인

## 개요

```
입력: /brainstorm [주제/질문] [--rounds N] [--fast] [--judge-only]

[Phase 0] 컨텍스트 분석
  └─ bs-orchestrator: 주제 분석 + 제약 조건 파악 + 성공 기준 정의

[Phase 1-N] 토론 라운드 (기본 3회)
  ├─ bs-debater-a: 확장적 관점 ("Yes, and...")
  └─ bs-debater-b: 검증적 관점 ("Yes, but...")
     ↓
  bs-orchestrator: 라운드 요약 + 합의점 추출

[Phase 마지막] 합의 또는 Judge 에스컬레이션
  합의 시: 실행 방안 3가지 도출 + 세션 종료
  미합의 시: bs-judge → 최종 판정 + 3단계 실행 방안
```

## 파라미터

| 파라미터 | 기본값 | 설명 |
|---------|--------|------|
| 주제/질문 | (필수) | 브레인스토밍할 주제 또는 결정 질문 |
| --rounds | 3 | 토론 라운드 수 (3-5) |
| --fast | false | 빠른 모드: 각 발언 요약 형식 |
| --judge-only | false | 토론 생략, 바로 Judge 판정 요청 시 |

## Phase 0: 컨텍스트 분석

`bs-orchestrator` 활성화:

```
다음 브레인스토밍 세션을 시작하세요:

주제: [주제]
라운드 수: [N]
제약 조건: [시간/자원/기술 한계 — 알려진 경우]

수행할 것:
1. 주제 분석 (무엇을 결정/탐색하려 하는가)
2. 성공 기준 정의 (좋은 답변의 조건)
3. Debater A와 B에게 Round 1 시작 신호
4. /tmp/brainstorm/session.md 파일 생성 및 세션 기록
```

## Phase 1-N: 토론 라운드

각 라운드는 다음 순서로 진행됩니다:

### A 발언 (먼저)
`bs-debater-a` 활성화:
```
/tmp/brainstorm/session.md 의 현재까지 내용을 읽고
Round [N]의 확장적 관점을 제시하세요.
이전 라운드와 다른 각도의 새로운 확장 포인트를 찾으세요.
```

### B 발언 (A 완료 후)
`bs-debater-b` 활성화:
```
/tmp/brainstorm/session.md 의 현재까지 내용, 특히 A의 Round [N] 발언을 읽고
검증적 관점을 제시하세요.
A의 핵심 가치를 인정한 뒤 핵심 장벽을 제시하세요.
```

### 오케스트레이터 요약
`bs-orchestrator`:
```
Round [N] 양측 발언을 요약하고:
1. 합의된 것 목록
2. 쟁점 목록
3. 다음 라운드 초점 (또는 합의 선언)
결과를 /tmp/brainstorm/session.md 에 추가
```

## Phase 마지막: 수렴 또는 Judge

### 합의 달성 시 (오케스트레이터 판단)
```markdown
## 합의 완료

### 합의된 실행 방안
1. [방안 1] — 담당: 본인 / 기간: [기간]
2. [방안 2] — 담당: 본인 / 기간: [기간]
3. [방안 3] — 담당: 본인 / 기간: [기간]

### 중단 기준
- [이 조건 발생 시 재검토]
```

### 미합의 시 → Judge 에스컬레이션

`bs-judge` 활성화:
```
/tmp/brainstorm/session.md 전체를 읽고 최종 판정을 내리세요.
판정 기준: 실현가능성 40% + 잠재가치 40% + 리스크관리 20%
3단계 실행 방안과 중단 기준을 포함하세요.
```

## --fast 모드

각 발언이 표준 형식 대신 다음 압축 형식으로 출력:

```
A[N]: [핵심 주장 1문장] + [근거 1개]
B[N]: [핵심 우려 1문장] + [해결 조건 1개]
Sync[N]: 합의=[Y/N], 다음 포인트=[한 줄]
```

## --judge-only 모드

토론 생략, 주제만 받아서 Judge 직행:
- bs-judge가 주제를 직접 분석하고 판정
- 긴급 결정이 필요할 때 사용

## 세션 파일 형식

`/tmp/brainstorm/session.md`:

```markdown
# 브레인스토밍 세션

## 주제: [주제]
## 시작: [날짜]
## 라운드: [N]회 예정

## 컨텍스트
- 목표: [결정/탐색할 것]
- 제약: [알려진 제약]
- 성공 기준: [조건]

---

## Round 1

### Debater A
[발언]

### Debater B
[발언]

### 오케스트레이터 요약
- 합의: [항목]
- 쟁점: [항목]

---

## 최종 결론

[합의 내용 또는 Judge 판정]
```

## 사용 예시

```bash
# 기본 브레인스토밍
/brainstorm "스마트스토어와 Shopify 중 어디에 더 집중할까"

# 빠른 모드
/brainstorm "신규 강의 주제 결정" --fast

# 라운드 수 지정
/brainstorm "SNS 채널 전략 수립" --rounds 5

# 즉시 Judge 판정
/brainstorm "유튜브 채널명 결정" --judge-only
```

## 에러 처리

| 상황 | 대응 |
|------|------|
| 주제 불명확 | 오케스트레이터가 명확화 질문 |
| 토론이 같은 논점 반복 | 오케스트레이터가 새 각도 제시 |
| Judge 판정 후 이의 | 새 세션으로 재브레인스토밍 |
| 제약 조건 미지정 | 1인 창업자 기본 제약 가정 |

## 관련 에이전트

| 에이전트 | 역할 | 모델 |
|--------|------|------|
| bs-orchestrator | 세션 MC + 합의 도출 | sonnet |
| bs-debater-a | 확장적 관점 | sonnet |
| bs-debater-b | 검증적 관점 | sonnet |
| bs-judge | 최종 판정 | opus |
