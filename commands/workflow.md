# Workflow Pipeline

`/workflow [기능 설명]` 실행 시 아래 5단계 파이프라인을 순서대로 진행한다.

```
PLAN → TDD → CODE REVIEW → COMMIT → PR
```

각 단계는 이전 단계가 완료되어야 다음 단계로 진행된다.
`--auto` 플래그가 없으면 각 단계 전에 사용자 확인을 요청한다.

---

## 인자 파싱

`$ARGUMENTS`에서 옵션 추출:
- `--skip-tdd` → TDD 단계 스킵 (이미 구현된 코드에 적용 시)
- `--skip-review` → 코드 리뷰 단계 스킵
- `--draft` → Draft PR 생성 (머지 안 함)
- `--auto` → 모든 단계 자동 진행 (사용자 확인 없음)
- 나머지 텍스트 → 기능 설명 (`$FEATURE`)

`$FEATURE`가 없으면:
```
기능 설명이 필요합니다.

사용법: /workflow [기능 설명] [옵션]

예시:
  /workflow 상품 상세 페이지에 리뷰 작성 기능 추가
  /workflow 로그인 버그 수정 --skip-tdd
  /workflow API 리팩토링 --auto
```
→ 중단

---

## 파이프라인 상태 출력 함수

각 단계 시작 전 아래 형식으로 현재 진행 상태를 출력한다:

```
════════════════════════════════════════════════════════════════
  Workflow Pipeline: [기능 설명 (30자 이하로 축약)]
════════════════════════════════════════════════════════════════
  [✅ DONE ] 1. PLAN       계획 확정
  [⏳ RUN  ] 2. TDD        현재 실행 중
  [⬜ WAIT ] 3. REVIEW     대기
  [⬜ WAIT ] 4. COMMIT     대기
  [⬜ WAIT ] 5. PR         대기
════════════════════════════════════════════════════════════════
```

아이콘 의미:
- `✅ DONE` — 완료
- `⏳ RUN` — 현재 실행 중
- `⬜ WAIT` — 대기
- `⏭ SKIP` — 스킵됨
- `❌ FAIL` — 실패

---

## STAGE 1: PLAN (기획)

파이프라인 상태 출력 (1단계 실행 중).

**목표**: 구현 계획을 수립하고 사용자 확인을 받는다.

### 1-1. 현재 프로젝트 컨텍스트 수집

```bash
git status --short 2>/dev/null | head -10
git log --oneline -5 2>/dev/null
ls -la 2>/dev/null | head -20
```

### 1-2. 계획 수립

planner 에이전트로 구현 계획을 작성한다:

1. **요구사항 재명확화**: `$FEATURE`를 구체적인 구현 항목으로 분해
2. **영향 파일 목록**: 변경이 필요한 파일과 그 역할
3. **구현 단계**: Phase별 작업 순서 (의존성 고려)
4. **리스크 식별**: HIGH/MEDIUM/LOW 분류
5. **복잡도 평가**: High/Medium/Low

출력 형식:
```
# 구현 계획: [기능명]

## 요구사항
[명확화된 요구사항]

## 영향 파일
| 파일 | 변경 유형 | 설명 |
|------|----------|------|
| [경로] | [Create/Modify/Delete] | [역할] |

## 구현 단계
### Phase 1: [이름]
- [ ] [작업 1]
- [ ] [작업 2]

### Phase 2: [이름]
- [ ] [작업 3]

## 리스크
- HIGH: [리스크]
- MEDIUM: [리스크]

## 복잡도: [High/Medium/Low]
예상 파일 변경: [N]개
```

### 1-3. 계획 저장

확인 전 계획을 `prompt_plan.md`에 저장:
- 기존 `prompt_plan.md`가 있으면 이전 내용을 `## 이전 계획` 섹션으로 아카이브 후 덮어쓰기

### 1-4. 확인 요청 (`--auto` 없을 때)

```
📋 계획이 준비되었습니다. 위 계획으로 진행할까요?

  y / yes    — 다음 단계(TDD)로 진행
  m / modify — 계획 수정 요청
  n / no     — 파이프라인 중단
```

`--auto` 플래그 시 → 확인 없이 진행

**사용자가 "no"** → 파이프라인 중단 메시지 출력 후 종료
**사용자가 "modify"** → 수정 사항 입력 받아 1-2단계 재실행
**사용자가 "yes"** → Stage 2로 진행

## STAGE 2: TDD (테스트 주도 개발)

`--skip-tdd` 옵션 시:
```
  [⏭ SKIP ] 2. TDD        --skip-tdd 옵션으로 스킵됨
```
→ Stage 3으로 진행

파이프라인 상태 출력 (2단계 실행 중).

**목표**: 테스트를 먼저 작성하고 구현한다.

### 2-1. TDD 사이클 실행

tdd-guide 에이전트로 Phase 1부터 순서대로 구현:

각 Phase에 대해:
1. **인터페이스 정의** — 타입/인터페이스를 먼저 정의
2. **테스트 작성 (RED)** — 실패하는 테스트 작성
3. **테스트 실행** — 실패 확인 (실패해야 정상)
4. **최소 구현 (GREEN)** — 테스트를 통과시킬 최소 코드 작성
5. **테스트 실행** — 통과 확인
6. **리팩토링** — 코드 품질 개선 (테스트 유지)
7. **커버리지 확인** — 80% 이상 달성

### 2-2. 테스트 실행 명령 (프로젝트 타입 자동 감지)

```bash
# Node.js
npm test 2>/dev/null || npx jest 2>/dev/null || npx vitest run 2>/dev/null
# Python
python -m pytest 2>/dev/null
# Go
go test ./... 2>/dev/null
```

테스트 실패 시 → 수정 후 재실행 (최대 3회 재시도)
3회 실패 시:
```
TDD 단계 실패 — 수동 개입이 필요합니다.

선택:
  c / continue — 실패 상태로 다음 단계 진행 (권장하지 않음)
  r / retry    — TDD 재시도
  s / stop     — 파이프라인 중단
```

### 2-3. 커버리지 검증

커버리지 80% 미만이고 `--auto` 없을 때:
```
커버리지가 [X]%입니다 (기준: 80%). 계속 진행할까요?

  y — 계속 진행
  n — 테스트 추가 후 재시도
```

---

## STAGE 3: CODE REVIEW (코드 리뷰)

`--skip-review` 옵션 시:
```
  [⏭ SKIP ] 3. REVIEW     --skip-review 옵션으로 스킵됨
```
→ Stage 4로 진행

파이프라인 상태 출력 (3단계 실행 중).

**목표**: 보안 취약점과 코드 품질 이슈를 발견하고 수정한다.

### 3-1. 변경 파일 수집

```bash
git diff --name-only HEAD 2>/dev/null
```

### 3-2. 보안 검사 (CRITICAL)

각 변경 파일에서:

| 검사 항목 | 심각도 |
|-----------|--------|
| 하드코딩된 시크릿 (API 키, 토큰, 비밀번호) | CRITICAL |
| SQL 인젝션 (문자열 보간 쿼리) | CRITICAL |
| XSS 취약점 (미검증 HTML 렌더링) | HIGH |
| 민감 데이터 로깅 (비밀번호·토큰 console.log) | HIGH |
| 하드코딩된 URL/키 (환경변수 미사용) | MEDIUM |
| 잘못된 CORS 설정 | MEDIUM |
| 인증 우회 패턴 | HIGH |

### 3-3. 코드 품질 검사

| 항목 | 기준 | 심각도 |
|------|------|--------|
| 함수 길이 | > 50 lines | HIGH |
| 파일 길이 | > 800 lines | HIGH |
| 중첩 깊이 | > 4 levels | HIGH |
| 에러 처리 누락 | try-catch 없음 | HIGH |
| console.log 잔존 | 프로덕션 코드 | MEDIUM |
| 변이 패턴 | 직접 객체 수정 | MEDIUM |
| 입력 검증 누락 | 외부 데이터 미검증 | HIGH |

### 3-4. 리뷰 결과 출력

```
────────────────────────────────────────────────────────────────
  Code Review Report
────────────────────────────────────────────────────────────────
  검사 파일: [N]개

  CRITICAL: [N]건
    [파일:라인] [설명] [수정 제안]

  HIGH: [N]건
    [파일:라인] [설명]

  MEDIUM: [N]건
    [파일:라인] [설명]
────────────────────────────────────────────────────────────────
```

### 3-5. 이슈 처리

**CRITICAL 발견 시** → 자동 수정 시도 → 수정 불가 시 사용자에게 수정 요청 후 대기

**HIGH 발견 시 + `--auto` 없을 때**:
```
HIGH 이슈 [N]건이 발견되었습니다.

  f / fix    — 자동 수정 시도
  i / ignore — 이슈 무시하고 진행 (권장하지 않음)
  s / stop   — 수동 수정 후 /workflow 재실행
```

**이슈 없음 또는 MEDIUM/LOW만** → Stage 4로 자동 진행

## STAGE 4: COMMIT (커밋)

파이프라인 상태 출력 (4단계 실행 중).

**목표**: 변경사항을 커밋하고 원격 저장소에 푸시한다.

### 4-1. 스테이징

```bash
git add -A
git diff --staged --stat
```

### 4-2. 커밋 메시지 자동 생성

Conventional Commits 형식으로 변경 내용 분석:

| Type | 조건 |
|------|------|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변화 없는 코드 개선 |
| `test` | 테스트만 변경 |
| `docs` | 문서만 변경 |
| `chore` | 빌드/설정 변경 |

`--auto` 없을 때:
```
커밋 메시지: "[생성된 메시지]"

  y — 이 메시지로 커밋
  e — 직접 입력
```

### 4-3. 브랜치 확인

main/master 브랜치 직접 커밋 시:
```
⚠️  main 브랜치에서 작업 중입니다.

  b / branch — 기능 브랜치 생성 후 푸시 (권장)
  y / yes    — main에 직접 푸시
  n / no     — 중단
```

### 4-4. 커밋 & 푸시

```bash
git commit -m "[커밋 메시지]"
git push 또는 git push --set-upstream origin [브랜치명]
```

## STAGE 5: PR (풀 리퀘스트)

파이프라인 상태 출력 (5단계 실행 중).

**목표**: PR을 생성하고 파이프라인을 완료한다.

### 5-1. PR 정보 수집

```bash
git log origin/main..HEAD --oneline 2>/dev/null || git log --oneline -5
git diff origin/main..HEAD --stat 2>/dev/null
```

### 5-2. PR 본문 자동 생성

```markdown
## 개요
[기능 설명]

## 구현 내용
[커밋 목록]

## 변경 파일
[git diff --stat 결과]

## 테스트
- [x] 단위 테스트 (TDD 방식)
- [x] 커버리지 [X]% 달성
- [x] 코드 리뷰 완료

## 보안 검토
- 보안 스캔: [pass / warn / skipped]
- 발견 이슈: [없음 / 수정 완료]

## 체크리스트
- [x] 빌드 통과
- [x] 테스트 통과
- [x] 코드 스타일 준수
- [x] 불변 패턴 사용 (변이 없음)
```

### 5-3. PR 생성

```bash
# Draft PR (--draft 플래그 시)
gh pr create --draft --title "[커밋 메시지]" --body "[본문]"

# 일반 PR
gh pr create --title "[커밋 메시지]" --body "[본문]"
```

### 5-4. 완료 출력

```
════════════════════════════════════════════════════════════════
  Workflow Pipeline Complete ✅
════════════════════════════════════════════════════════════════

  [✅ DONE ] 1. PLAN       계획 확정 (prompt_plan.md 저장됨)
  [✅ DONE ] 2. TDD        테스트 [N]개 통과, 커버리지 [X]%
  [✅ DONE ] 3. REVIEW     이슈 [N]건 발견 및 수정
  [✅ DONE ] 4. COMMIT     [커밋 해시] [커밋 메시지]
  [✅ DONE ] 5. PR         #[PR번호]: [PR URL]

  총 변경 파일: [N]개

────────────────────────────────────────────────────────────────
  다음 단계
────────────────────────────────────────────────────────────────
  PR 리뷰 후 머지  →  /commit-push-pr --merge
  배포 검증        →  /handoff-verify
  문서 업데이트    →  /sync-docs
════════════════════════════════════════════════════════════════
```

## 파이프라인 중단 처리

어느 단계에서든 중단 시:

```
════════════════════════════════════════════════════════════════
  Workflow Pipeline 중단
════════════════════════════════════════════════════════════════

  [✅ DONE ] 1. PLAN       완료
  [✅ DONE ] 2. TDD        완료
  [❌ FAIL ] 3. REVIEW     CRITICAL 이슈 미해결로 중단
  [⬜ WAIT ] 4. COMMIT     미실행
  [⬜ WAIT ] 5. PR         미실행

  재개 방법:
    이슈 수정 후 → /workflow [기능 설명] --skip-tdd
════════════════════════════════════════════════════════════════
```

## 사용 예시

```bash
# 기본 실행 (전체 단계, 각 단계 확인 요청)
/workflow 상품 상세 페이지에 리뷰 작성 기능 추가

# 이미 구현된 코드에 리뷰+커밋만 실행
/workflow 로그인 버그 수정 --skip-tdd

# 모든 단계 자동 실행 (확인 없음)
/workflow API 엔드포인트 리팩토링 --auto

# Draft PR로 생성 (리뷰 후 머지)
/workflow 결제 기능 구현 --draft

# TDD, 리뷰 모두 스킵 (빠른 커밋용)
/workflow typo 수정 --skip-tdd --skip-review

# 자동 + Draft PR
/workflow 실험적 기능 --auto --draft
```

## 인자 요약

| 인자 | 설명 |
|------|------|
| `[기능 설명]` | 구현할 기능 (필수) |
| `--skip-tdd` | TDD 단계 스킵 |
| `--skip-review` | 코드 리뷰 단계 스킵 |
| `--draft` | Draft PR 생성 |
| `--auto` | 모든 단계 자동 진행 |
